Fixes for the problems people usually hit, a prompt to get unstuck, and the words you'll hear today.

The fix-it prompt

When anything breaks, fill in the blanks and send this to Gemini in the same chat.

I got this error: [paste the exact error message here] I expected: [what should happen] But instead: [what actually happened] Please explain the cause in simple terms, fix it, and give me the FULL updated Code.gs and Index.html. Don't provide patches.

Errors show up on the web page, in the Apps Script editor, or under Executions in the Apps Script left sidebar. If Gemini goes in circles after 3 or 4 tries, start a new chat and paste your latest full Code.gs and Index.html with the problem.

Common errors and fixes

Click a problem to see the likely cause and fix.

null"Cannot read properties of null (reading 'appendRow')" or similar

Cause: the script can't find your sheet tab.

Fix: check that the Sheet ID in Code.gs is correct, and that the sheet name matches your tab name exactly, including capital letters and spaces (for example Sheet1). Use the Sheet ID helper. Save, then deploy a new version.

no changeI fixed the code, but the web app looks the same

Cause: saving only updates the editor.

Fix: Deploy › Manage deployments › pencil › Version: New version › Deploy. Then refresh the web app page. See Step 10.

loadingThe bookings table is stuck on "Loading…" or shows nothing

Likely cause: the code sends date or time values from the Sheet straight to the page. Apps Script can't pass those Date objects to the browser, so the result arrives empty.

Fix: tell Gemini: "The bookings table stays empty. Please convert all dates and times to text before returning them to the page." Ask for the full updated code.

permission"You do not have permission" or "Authorisation is required"

Cause: the script needs permission again, often after new features are added, such as sending emails.

Fix: deploy a new version and open the link again. When Google asks, review permissions and allow access with your UniMAP account.

accountsErrors appear only in my browser, or the wrong account is used

Cause: several Google accounts are signed in to the same browser. Apps Script web apps don't handle this well.

Fix: open the web app in an incognito window, or a separate browser profile, signed in with your UniMAP account only.

not found"Script function not found: doGet" or a blank page

Cause: Code.gs wasn't saved, doGet is missing, or the HTML file name doesn't match.

Fix: make sure your HTML file is named exactly Index, matching the name used in doGet. Save both files, then deploy a new version.

adminThe Admin Dashboard tab doesn't appear for me

Cause: your email isn't in the admin list exactly as the script expects, or the old version is still live.

Fix: check the admin list in your Sheet: the email must be exact, lowercase, with no extra spaces. Then deploy a new version and reload.

accessA colleague can't open my web app link

Cause: the access setting, or they're signed in with a non-UniMAP account.

Fix: in your deployment, "Who has access" must be Anyone within Universiti Malaysia Perlis. Your colleague must sign in with their UniMAP account.

patchesGemini gives me only part of the code ("replace lines 40 to 55…")

Fix: reply: "Please give me the full updated Code.gs and Index.html. Don't provide patches." Then select all, delete and paste the complete files.

cut offGemini's answer stops halfway through the code

Fix: reply "Continue exactly where you stopped." Or ask for one file at a time: "Give me only the full Code.gs first."

What's next: your own system

The same prompt chain works for other faculty processes. For example, a Title Proposal Vetting System: students submit FYP titles, lecturers review them, and a coordinator approves. Start with a Prompt 1 like this, then follow the same 12 steps.

Act as a Senior Web Systems Analyst. I want to build a simple Title Proposal Vetting System for the Faculty of Engineering Tech (FKTEN) using Google Apps Script and Google Sheets. Final-year students submit project title proposals. Supervisors review them, and the FYP coordinator makes the final decision. Based on this, please suggest: - 5 essential features for a simple, user-friendly web app. - What exact data fields we should store in Google Sheets for each proposal. - A logical workflow for the proposal status (e.g., Submitted, Reviewed, Approved, Needs Revision) between students, supervisors and the coordinator. Keep your suggestions simple, practical, and non-technical. Do not write the code yet; just outline the system design.
