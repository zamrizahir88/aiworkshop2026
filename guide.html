Act as a Senior Web Systems Analyst. I want to build a simple Online Room Reservation System for the Faculty of Engineering Tech (FKTEN) using Google Apps Script and Google Sheets. Our lecturers need to book specific shared rooms. The system must strictly limit the booking options to only the following 6 official rooms: Bilik Viva-Voce (FKTEN 1 – Blok 11, Aras Bawah) - Capacity: 7 Bilik Mesyuarat Utama (FKTEN 1 – Blok 11, Aras 1) - Capacity: 35 Bilik Diskusi (FKTEN 1 – Blok 11, Aras 1) - Capacity: 10 Dewan Serbaguna (FKTEN 1 – Blok 9, Aras 1) - Capacity: 100 Bilik Tutorial (FKTEN 1 – Blok 5, Aras 2) - Capacity: 50 Dewan Seminar (FKTEN 1 – Blok 5, Aras 2) - Capacity: 50 Based on these constraints, please suggest: - 5 essential features for a simple, user-friendly web app. - What exact data fields we should store in Google Sheets to capture the booking and room details. - A logical workflow for how to handle the booking status (e.g., Pending, Approved) between the user and admin. Keep your suggestions simple, practical, and non-technical. Do not write the code yet; just outline the system design.

Read the answer. This is your system design. If something doesn't fit how FKTEN works, tell Gemini now, before any code exists. Changes are cheapest at this stage.

Put the code into Apps Script

Delete the default code›Paste Code.gs›Set Sheet ID and name›+ › HTML, name it Index›Paste Index.html, save
📄 Code.gs
  1. In Code.gs, select all (Ctrl+A), delete, and paste the Code.gs from Gemini.
  2. Find the line with the Sheet ID and replace the placeholder with your own ID. Use the helper below.
  3. If there's a sheet name line, make sure it matches your tab name exactly (for example Sheet1).
  4. Click the + next to Files, choose HTML, and name it Index. Don't type ".html": it's added automatically.
  5. Delete the default content of Index.html, paste Gemini's Index.html, and save (Ctrl+S).
Sheet ID helper

Your Sheet ID is the part of your Sheet's link between /d/ and /edit:

https://docs.google.com/spreadsheets/d/1AbC...xYz/edit#gid=0
const SHEET_ID = 'paste your link above';
const SHEET_NAME = 'Sheet1';

Your AI-generated code may name these differently. Only replace the values inside the quotes.

Prompt 4
We are upgrading a Google Apps Script Room Reservation System to include role-based access. I need two roles for this system: - Admins: Me (my Google account: yourname@unimap.edu.my) and anyone else whose email I authorize. - Users: Other UniMAP Gmail accounts. Admin roles: - Can view all bookings made. - Can approve/reject bookings with optional remarks. User roles: - Can view the public schedule of bookings made by others. - Can submit a new booking request. Note: Admins also need to make bookings. Provide a clean UI switch (like tabs) for Admins to easily toggle between a "Booking View" (acting as a normal user) and an "Admin Dashboard". CRITICAL SECURITY & TECHNICAL CONSTRAINTS (MUST FOLLOW): - Workspace Deployment Rules: The app will be deployed using Execute as: Me (Developer) and Who has access: Anyone within unimap.edu.my (to bypass Google Drive file-sharing errors). You must capture user identities securely using Session.getActiveUser().getEmail(). - Strict Admin Validation (Backend): When cross-referencing the logged-in email with the Admin list in Google Sheets, you MUST implement strict validation. Explicitly reject null, undefined, or blank emails, and ignore empty rows in the sheet to prevent blank === blank false-positive admin access. - Server-Side Rendering (Frontend UI): Do NOT rely on CSS or JavaScript (e.g., display: none) to hide the Admin Dashboard from normal users. You MUST use Google Apps Script server-side scriptlets (e.g., <? if (isAdmin) { ?> ... <? } ?>) so the admin HTML and UI tabs are never physically sent to a non-admin's browser. Tell me if I need to make any modifications to the current Google Sheet database to support this. Update the .gs and .html files accordingly. Don't provide patches; output the fully updated code directly.
  1. Do any Sheet changes Gemini asks for first, such as adding an Admins tab with your email in it.

Challenges: try them one by one

In Gemini, then redeploy
AIFrontendBackendDatabase

Write your own prompt for each, using the 4 golden rules. Stuck? Open the hint. After each one: paste the full code, save, and deploy a new version.

✉️ Email the decision

Send a notification email once a booking is approved or rejected.

Need a hint?
Update the system so that when an admin approves or rejects a booking, the lecturer automatically receives an email with the decision, room, date, time and admin remarks. Output the fully updated Code.gs and Index.html. Don't provide patches.

👥 Manage admins on the website

Set the admin list through the website, not directly in the Google Sheet.

Need a hint?
Add a "Manage Admins" section inside the Admin Dashboard where admins can add or remove admin emails. Store the list in the admin sheet. Only admins can see or use it, using server-side scriptlets and server-side checks. Only accept emails ending in @unimap.edu.my. Output the fully updated Code.gs and Index.html. Don't provide patches.

🚫 Prevent clashing bookings

Stop two bookings for the same room at overlapping times.

Need a hint?
Before saving a new booking, check for any Pending or Approved booking in the same room on the same date with an overlapping time. If there is a clash, do not save it, and show a clear message naming the conflicting booking. Do this check in Code.gs on the server, not only in the browser. Output the fully updated Code.gs and Index.html. Don't provide patches.

📅 Show room availability

Show which time slots are taken before a lecturer books.

Need a hint?
When a lecturer selects a room and a date in the booking form, show the time slots already taken (Pending and Approved) for that room on that date, so they can choose a free slot. Update it automatically when the room or date changes. Output the fully updated Code.gs and Index.html. Don't provide patches.
